# Step 9 — Implement OpenPGP/MIME on the new seams

- Status: Done
- Depends on: Steps 5–8
- Issue: [#704](https://github.com/bbottema/simple-java-mail/issues/704)
- Primary areas: new optional OpenPGP module, configuration APIs, outbound and inbound protection handlers

## Goal

Implement RFC 3156 signing, encryption, verification, and decryption without bypassing the normal Mailer transport, proxy, batch, governance, logging, or receipt paths.

## Work

1. Add provider-neutral core configuration for a signing secret key/passphrase, recipient public keys, verification keys/keyrings, decryption secret keys/passphrase lookup, and optional algorithm preferences.
2. Keep key discovery, WKD, public keyservers, and application trust policy out of the initial release; accept in-memory key material without temporary user files.
3. Generate detached `multipart/signed` messages with `protocol="application/pgp-signature"` and a `micalg` matching the actual signature hash.
4. Sign the exact finalized first MIME entity, including its headers, blank line, transfer encoding, content, and nested boundaries.
5. Generate RFC 3156 `multipart/encrypted` messages with `protocol="application/pgp-encrypted"` and support multiple recipients.
6. Apply OpenPGP signing before encryption and DKIM after OpenPGP protection.
7. Register the OpenPGP inbound handler for detection, detached verification, decryption, and normal parsing of the effective clear entity.
8. Reject simultaneous S/MIME and OpenPGP configuration with a focused validation error.
9. Use independent Thunderbird/GnuPG fixtures in both directions; do not rely solely on round trips generated by the same implementation.

## Acceptance criteria

- [x] Signed plain text and signed `multipart/mixed` messages verify internally and with an independent fixture/client.
- [x] Non-ASCII, quoted-printable, base64, CRLF, attachment, embedded-image, calendar, and nested multipart cases verify.
- [x] Tampering yields `invalid`, while a missing public key yields `key missing/unverified`; readable clear content remains available.
- [x] Encrypted and signed-and-encrypted messages round-trip through the normal converter.
- [x] Multi-recipient encryption works and reports recipient key IDs where available.
- [x] Missing decryption keys preserve the original encrypted MIME data and return a specific status.
- [x] Signer key ID/fingerprint, signature/hash algorithms, encryption algorithm, and failure status are exposed without asserting trust.
- [x] DKIM plus OpenPGP plus bounce/DSN submits through the normal provider adapter and verifies after capture.
- [x] Parsing works predictably with and without `openpgp-module` present.
- [x] Secrets and passphrases never appear in logs, exceptions, serialization, or `toString()` output.

## Completion evidence

- `openpgp-module` implements detached RFC 3156 signing/verification and multi-recipient encryption/decryption with signing-before-encryption and bounded nested processing.
- Provider-neutral configuration and result APIs expose key identifiers, fingerprints, algorithms, status, and safe failure reasons without leaking Bouncy Castle types or claiming trust.
- `OpenPgpMimeTest` covers exact plain entities, complex nested MIME, tampering, missing verification keys, multi-recipient encryption, sign-then-encrypt, missing keys, wrong passphrases, module absence, redaction/serialization, and independent fixtures.
- Checked-in inbound fixtures were generated by OpenPGP.js 6.3.1. Its independent verifier also accepts the Simple Java Mail outbound signature and decrypts its ciphertext.
- `MailerLiveTest#protectedOpenPgpSurvivesAngusEightBitMimeTransport` sends DKIM plus OpenPGP plus bounce/DSN through real Angus and verifies the captured OpenPGP signature.
- Simultaneous S/MIME and OpenPGP configuration fails with a focused validation error.
