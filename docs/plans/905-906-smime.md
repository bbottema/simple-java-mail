## Impact map

| Path | Intended behavior and preserved boundary |
| --- | --- |
| `SmimeCryptoSupport.getStatus` -> `SMIMESupport.processIncomingEncrypted` | Standard and legacy opaque signed MIME declarations select signature inspection after successful decryption. Keep cryptographic validation at the optional module boundary. |
| Configured/static EML and MIME import -> preprocessing -> `Email` | Expose SIGNED_ENCRYPTED, DECRYPTED and the actual signature result on the outer Email, independently of signed-content merging. Retain original protected bytes, borrowed top-level streams and readable content. |
| Outlook attachment interpretation -> `Email` | Preserve the existing sole-attachment message-envelope boundary when propagating decrypted signature facts. A plain parent and a declared encrypted parent with additional independent protected files must not acquire those files' signature results. |
| `SMIMESupport.retrieveSmimeKeyFromPkcs12Keystore` from signing/decryption | Atomically reuse one successfully parsed key per equal immutable PKCS12 configuration, safely across shared concurrent module calls. Distinct configurations remain separate and failed loads remain uncached. Preserve #320 cache lifetime and performance policy; eviction is deferred. |
