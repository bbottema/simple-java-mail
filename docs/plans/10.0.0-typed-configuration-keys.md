## Contract and design

- One canonical ordinary read, `get(ConfigKey<T>)`, with invariant typed keys also used in both `valueOrProperty` overloads.
  Presence/provenance keep their existing method names and accept keys. Remove unsafe/scalar getter families without aliases.
- `ConfigKeys` declarations bind each parser and Java projection together; no independently maintained property/type table.
  Keys have no public constructor or extension registration. Keep Property for textual identities and explicit raw integration.
- Retain parser/lock/raw-source representations and all names, numeric units, range/precision, zero/false/unset, provenance,
  redaction, named isolation, detachment and feature-owner validation. Six integer-millisecond settings project to Duration;
  eight existing ISO-duration settings retain their distinct contracts.
- Missing scalars and aggregate configuration maps return null; configured wildcard maps retain precise generic types and
  detached immutability. Explicit/fallback objects selected by the helper retain their existing ownership.

## Execution ledger

### Implemented API and authoritative schema

`ConfigKey<T>` is final with no public constructor or extension registration. `ConfigKeys` has 111 canonical fields.
Each field selects a typed parser/projection factory in PropertySchema; that binding also parses the loader's value.
The old independent Property-to-ValueType table is removed. Diagnostic grouping/sensitivity retain their existing
central metadata and coverage check; catalogue initialization independently requires exactly one binding for every Property.

The supported snapshot contract has one `get(ConfigKey<T>)`, typed `hasProperty`/`getPropertySource`, and two invariant
`valueOrProperty` overloads. No scalar-name getter aliases, inferred-T Property getter, Class-requested read or new configuration
view hierarchy is retained. Source/type presence and fallback helpers do not use `ConfigKey<? extends T>`.

| Legacy raw property identity | Java key and view |
| --- | --- |
| DEFAULT_SESSION_TIMEOUT_MILLIS | SESSION_TIMEOUT / Duration |
| DEFAULT_ASYNC_QUEUE_WAIT_TIMEOUT_MILLIS | ASYNC_QUEUE_WAIT_TIMEOUT / Duration |
| DEFAULT_POOL_KEEP_ALIVE_TIME | THREAD_POOL_KEEP_ALIVE_TIME / Duration |
| DEFAULT_CONNECTIONPOOL_CLAIMTIMEOUT_MILLIS | CONNECTION_POOL_CLAIM_TIMEOUT / Duration |
| DEFAULT_CONNECTIONPOOL_EXPIREAFTER_MILLIS | CONNECTION_POOL_EXPIRE_AFTER / Duration |
| DEFAULT_CONNECTIONPOOL_EXPIREAFTERCREATION_MILLIS | CONNECTION_POOL_EXPIRE_AFTER_CREATION / Duration |

All other key names mirror their existing property identifiers. Property enum constants/textual names remain intact.
Raw storage, `asMap`, `asSourceMap`, locks and source round-trips keep existing Integer milliseconds. ISO-duration input
precision is unchanged. Runtime defaults, negative/zero feature semantics and optional-module validation stay with their
owners. A scalar key name can be used as dynamic input; aggregate namespaces still require individual child names.

Ordinary consumers use keys, including typed retry/failover/rate/duration helpers and Email governance. Dynamic lock
comparisons explicitly use raw maps. Typed protection-field helpers compare against the same lock name without adding
an application-facing internal bridge. Jakarta Mail/Spring Environment raw property helpers are not migrated by name.
The API expansion workflow now requires a catalogue binding rather than another type table.
