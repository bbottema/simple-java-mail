## Contract

- Both immutable configurations implement Serializable and retain all existing key, passphrase and algorithm choices.
- Deserialization uses the existing construction/copying boundary so serialized graph aliases cannot mutate restored values.
- Email retains both fields without changing its format version or either Email/InternalEmail serial UID.
- Earlier streams remain readable; state omitted by an earlier stream remains absent and cannot be recovered.
- Already protected exact EML keeps authoritative bytes and bypasses new protection/template processing after restoration.
- Signing snapshots include secret key rings and passphrases. Encryption-only configuration holds public key rings and cipher choice.
- Existing structural and borrowed-resource boundaries, copying, template precedence, redaction and optional-module ownership remain.
