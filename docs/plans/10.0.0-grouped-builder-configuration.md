# Group advanced builder configuration

Accepted on 20 October 2026 during the public API review. Governing decisions: ADR 0003, ADR 0031 and ADR 0018.

## Scope and implementation

- Keep ordinary SMTP setup and message composition direct.
- Mailer supplied choices use seven immutable core values: connection pool, asynchronous execution, SOCKS proxy, sending limits,
  connection, TLS and validation. Existing debug, telemetry, retry and handler values retain their independent scopes.
- Email supplied choices use image resolution, content encoding, template options and SMTP delivery. Exact Email shares the transport-only group.
- Remove moved scalar setters and their companions from supported root contracts. Internal scalar bridges retain existing runtime and CLI behavior.
- A replacement group restores captured members where it leaves choices unset. Explicit clearing stays distinct from inherited absence;
  mandatory locks, caller-Session baselines and optional-module semantic validation remain binding.
- Async queue choices use `rejectWhenFull()` or `waitForCapacity(Duration)`. `resetQueue()` selects the existing built-in queue defaults.
- Configuration construction creates no workers/connections and consumes no message content. Borrowed executors, SSL factories and content retain their owner.
- Migrate tests, core-only/JPMS consumers, CLI adapters, Spring callers, current feature examples and released-9.x migration guidance.

This implementation preserves address parsing and Reply-To accumulation. The accepted follow-on address-convenience work is a separate checkpoint.

### Accepted handler-factory documentation pattern

The accepted documentation-only decision 4 preserves the existing factory and send signatures. The website now contains
`sending-and-execution.hbs#section-correlate-application-jobs`, linked from the field guide. Its application-owned helper and complete wiring
example live in `simplejavamail.org/src/assets/guides/job-correlation/`, with an executable fixture under
`simplejavamail.org/tests/application-examples/JobCorrelatedMailerTest.java`.

The pattern captures business job ID and observation UUID in factory-created closures, immediately restores/removes ThreadLocal context,
and explains individual-send versus lazy-batch timing, Message-ID distinction, retries/failover, lossy progress and borrowed executor ownership.
All three Java sources compile with `--release 11`; 24 synthetic concurrent/queued/rejection/context cases pass without SMTP.
Website checks/build and 5,598 internal links pass. The follow-on exception-contract job must keep these three sources compiling.
