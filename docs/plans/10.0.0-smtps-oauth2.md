## Execution ledger

### Implementation

`SMTPS_OAUTH2` delegates its property names, default port and QUIT setting to `SMTPS`, adds XOAUTH2 and preserves its own
strategy marker. Fixed-token construction, provider validation, protocol-specific username/mechanism selection and locked
password mapping recognize both OAuth2 presets. The managed Angus provider/probe/progress paths already select their
transport and TLS behavior by `smtp` versus `smtps`; no provider implementation or execution-stage rewrite was necessary.

A regular owned `SMTPS_OAUTH2` Session rejects a contradictory `mail.transport.protocol` override before resource setup,
including a locked extra property. The existing STARTTLS guard is unchanged. The fixed-token lock now compares the token
instead of requiring the unrelated password-Authenticator `mail.*.auth=true` flag; both OAuth2 presets are covered.
Caller-owned Sessions retain their original provider and trust/identity choices. No identifier/result-absence API was changed.
The send-phase/ownership catalogue and diagrams are unchanged because this preset follows the existing implicit-TLS path.
