# Caller-Session and recipient-group reset verification

Scope: the two approved slices in [the implementation plan](../plans/10.0.0-caller-session-and-recipient-group-resets.md), following ADRs
0001, 0003, 0015, 0021, 0025, 0031 and 0036. This evidence is separate from the earlier, still-uncommitted API contract-hardening work.

## TDD evidence

- The caller-Session tests first reproduced ignored explicit overrides, inherited-default replacement, an incorrect common timeout,
  marker-dependent behavior and opaque-protocol handling before the production correction.
- The recipient reset API first failed compilation because it did not exist. With declarations and deliberately no-op implementations,
  all four behavioral regressions failed: a no-op cannot restore original certificate/NOTIFY metadata. The real transitions then passed.
- The combined meaningful red run reported 18 tests, 15 assertion failures and one lock-related error. Log:
  `tmp/api-hardening/caller-session-group-behavior-red.log`. Earlier fixture spelling/entry-point mistakes are not claimed as behavioral evidence.
- Additional controls exposed the need to preserve unmarked OAuth2 Session credential selection and Boolean-valued provider settings.
  Log: `tmp/api-hardening/caller-session-edge-red.log`.
- Inherited Properties defaults and marker-free TLS lock checks have independent failing-before-fix evidence in
  `tmp/api-hardening/caller-session-defaults-tls-red.log`.
- The existing construction-race test caught an important snapshot detail: mutating a cloned Properties subclass can execute application
  mutation hooks before ownership. Detached overlays now use plain Properties, preserving the inherited defaults separately. The original
  race assertions remain intact, not relaxed.

The correction retains positive controls for library-owned defaults and direct constructor fixtures. Explicit null timeouts remain invalid;
an unavailable inspection value must not become an accidental request to remove socket timeouts.
