# Grouped public API Javadoc preservation audit

Status: PASS. Independent baseline comparison, Javadoc preservation repairs, fresh generated HTML, packaged Javadocs and coordinated CLI verification complete (20 October 2026).

## Scope and provenance

This is a fresh independent comparison of useful public contracts, not a compilation-only review. The baseline is Git object
`69c483280394a743b5b73312ed0fcfc3dfd972d5`, the actual pre-grouping source. At the time of this comparison, HEAD still pointed to that object
and the grouped implementation was the dirty working tree. Nothing was staged, reverted, committed, pushed or published by this audit. Existing staged/unstaged/untracked
work and the nested website were left in place. No later parsing, Reply-To or exception work is part of the audit.

The inventory was extracted independently from `git show <baseline>:<path>` and current source. `target/grouped-*.json` metadata was used
as a navigation aid, then corrected against the real public destinations. In particular its obsolete mappings of queue reset, executor
reset, proxy clearing and local-address inspection were not treated as API truth.

## Intentional migration differences

- All moved scalars, getters and clearing/resetting companions disappear from supported root Java builders; group builders now own those choices.
  CLI/internal adapters keep old mechanics and scalar names without becoming supported root API. The two proxy convenience overloads are
  expressed by immutable endpoint/authentication choices, and the five positional crypto overloads by existing feature builders.
- Reassigning a group replaces supplied choices; unset members inherit captured configuration, never earlier group state. Getters expose
  supplied absence and clear flags; `OperationalConfig`, `ProxyConfig`, `EmailGovernance` and completed Email getters retain resolved read roles.
  Per-cluster configuration still falls back to the effective regular pool setting, rather than independently reloading properties.
- The Java queue uses `rejectWhenFull()` or `waitForCapacity(Duration)` instead of enum+separate-timeout setters. The scalar enum/properties/CLI
  remain. Java wait has a required explicit positive duration; property-backed/reset wait remains one second. Queue reset maps to `resetQueue()`,
  not `useConfiguredCapacityPolicy()`; executor reset maps to `clearExecutorService()`, not inheritance restoration.
- Shared `SmtpDeliveryOptions` deliberately accepts nullable ReturnOption for clearing, preserving composed-Email semantics. The removed exact
  scalar @NotNull signature no longer exists; the required nonnull root group is the new public null-validation boundary. Valid NOTIFY controls,
  exact-byte preservation, provider requirements and mandatory locks remain. Envelope-ID validation occurs at complete-request inspection/build.
- Encoding-group clear removes a supplied choice so composed governance and the normal quoted-printable fallback can apply. To explicitly choose
  quoted-printable, use the typed setter. This follows the accepted group absence/replacement model rather than retaining the removed scalar helper
  that assigned quoted-printable directly. Body-specific clears retain common-encoding fallback after governance.
- Default constants stay on the key root builders. Values/builders do not load sources, allocate executors/connections or read message content;
  crypto File/Path/input overloads intentionally read their explicit key/certificate input as already documented.
